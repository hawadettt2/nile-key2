### قسم تكميلي: الافتراضات والقيود وحدود الإنفاذ
- **الافتراضات:**
  - Code يعمل في نطاق `IMPLEMENTATION_SCOPE.md` المعتمد.
  - Bash = ask: كل أمر bash يتطلب موافقة (ask) قبل التنفيذ.
  - Edit/Write = allow ضمن النطاق: التعديلات المسموحة، لكن Bash ask يوافق على الأوامر.
- **القيود:**
  - **Bash ask لا يوفر عزلًا أمنيًا للمسارات**: موافقة Bash تعني الموافقة على سلسلة الأمر، لا على كل مسار يلمسه الأمر.
  - **Edit/Write allow ضمن النطاق**: لا حماية مسار تقنية مثبتة (التقرير 8.4.15/8.4.16: ShellTool.collect استشاري).
- **حدود الإنفاذ (وفق تقرير المرحلة الأولى):**
  - Bash = ask: موافقة على سلسلة الأمر؛ لا فحص مسار (`assert bash` @109,207,519).
  - Edit/Write = allow: قاعدة `edit`؛ الأنماط (إن وجدت) تُقيّد الأداة، لا Bash.
  - Task = deny: لا تفويض.
  - **لا حماية مسار شاملة**؛ الحماية = قرار bash (ask) + Edit/Write scope + OS sandbox (غير متاح على Windows، E27).
- **المصدر:** التقرير 8.4.15–8.4.18؛ قرار 5؛ قرار المالك (Bash=ask).

### قسم تكميلي: ملاحظات
- **فصل مثبت/معتمد:** الحالة الحالية (Bash allow، Edit/Write allow، Task allow موروثة) **مثبتة** من E1–E28؛ الهدف (Bash **ask**، Edit/Write allow ضمن النطاق، Task **deny**) **معتمد من المالك** (2026-11-20).
- **نقاط تحتاج مراجعة:** أمثلة الملفات/الامتدادات إرشادية (لا قيود تقنية)؛ حدود الإنفاذ (القسم التكميلي).
- **المرجع:** الخطة 351، 366؛ التقرير 8.4.13، 8.4.15–8.4.18؛ قرار 5، 10؛ قرار المالك (Bash=ask).
