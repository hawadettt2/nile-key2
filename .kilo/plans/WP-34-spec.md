## 1. Executive Summary

WP-34 introduces the **External Research Capability** to the Nile Key Intelligent Operating Platform. This capability enables the Digital Export Manager (DEM) to actively search, retrieve, and organize information from external sources in response to business queries, transforming raw external information into structured, traceable research results that downstream Reasoning and Planning layers can consume.

This Work Package is **foundational** for the Executive Intelligence Layer:
- It does not make business decisions.
- It does not generate final business analysis.
- It does not execute plans or ERP operations.
- It does not replace or subsume Knowledge Ingestion.

**Source:** PLAN.md Section 15.3 (Phase 2 — Intelligence Expansion), `.kilo/plans/KNOWLEDGE_INGESTION_CONTRACT.md` Section 3.1/9.

## 3. Objectives

1. Enable DEM to accept structured Research Requests from users or missions.
2. Execute research lifecycle from request to structured result.
3. Retrieve information from multiple external sources.
4. Capture source identity, URL/reference, and retrieval timestamp for every result.
5. Associate evidence with research results.
6. Produce structured output consumable by Reasoning and Planning layers.
7. Handle source failures gracefully without blocking the research lifecycle.
8. Maintain clear architectural boundaries with Knowledge Ingestion, Reasoning, and Execution.

**Source:** PLAN.md Section 15.3, ARCH review 2026-08-09.

## 5. Research Lifecycle

The External Research Capability follows this lifecycle:

```
Research Request
    ↓
Query/Research Planning
    ↓
Source Discovery
    ↓
Retrieval (per source)
    ↓
Content Processing
    ↓
Evidence/Source Capture
    ↓
Result Structuring
    ↓
Research Result
```

### 5.1 Research Request
Structured input capturing:
- Research goal/question
- Context (session, user, mission)
- Scope constraints (domains, regions, time ranges)
- Source preferences or exclusions

### 5.2 Query/Research Planning
Decompose the request into:
- Sub-queries
- Source selection strategy
- Retrieval parameters

### 5.3 Source Discovery
Identify relevant external sources based on:
- Request scope
- Source registry/configuration
- Source availability

### 5.4 Retrieval
Fetch content from each discovered source:
- Respect source-specific constraints (rate limits, auth)
- Handle timeouts and failures per source
- Record retrieval status per source

### 5.5 Content Processing
Transform raw retrieved content:
- Extract relevant information
- Normalize format
- Prepare for structuring

### 5.6 Evidence/Source Capture
For each piece of information:
- Record source identity
- Record source URL/reference
- Record retrieval timestamp
- Associate with research result

### 5.7 Result Structuring
Organize processed content into:
- Structured research result
- Source citations
- Evidence associations
- Confidence indicators (where applicable)

### 5.8 Research Result
Final output consumable by Reasoning layer:
- Structured findings
- Source provenance
- Evidence references
- Retrieval metadata

## 6. Sources Model

### 6.1 Source Identity
Each external source must have:
- Unique identifier
- Human-readable name
- Type classification (e.g., "market_data", "regulation", "news", "trade_statistics")
- Base URL or connection reference

### 6.2 Retrieval Metadata
Each retrieval operation must capture:
- Source identifier
- Source URL/endpoint used
- Retrieval timestamp (ISO-8601)
- Success/failure status
- Error details if failed

### 6.3 Evidence Association
Each research result item must associate with:
- Source identifier
- Source URL/reference
- Retrieval timestamp
- Raw content reference (if available)

### 6.4 Multi-Source Handling
- Research may query multiple sources in parallel or sequence
- Each source result is captured independently
- Final result aggregates across sources with provenance

### 6.5 Source Failure Handling
- Source failure does not block entire research
- Failed sources are recorded with error metadata
- Partial results from available sources are returned
- Research result indicates source coverage

## 7. Evidence & Provenance

### 7.1 Source Provenance Requirements
Every research result item must preserve:
- **Source ID:** Unique identifier of the source
- **Source URL/Reference:** Exact location of the information
- **Retrieval Timestamp:** ISO-8601 timestamp of when data was retrieved
- **Evidence Association:** Link to raw evidence or excerpt

### 7.2 Traceability
- Research results must be traceable to their sources
- Aggregated findings must preserve per-source provenance
- Reasoning layer can trace any claim back to its source

### 7.3 No LLM-as-Truth Principle
- LLM may assist in processing or summarizing
- LLM output must be linked to underlying sources
- LLM-generated content without source backing must be flagged

---

## 8. Verification & Quality

### 8.1 Architectural Requirements
- Source retrieval must be verifiable (success/failure logged)
- Result structuring must be deterministic for same inputs
- Evidence capture must be non-repudiable

### 8.2 Quality Indicators
- Source reliability metadata captured at source level
- Retrieval success/failure tracked per source
- Freshness indicated by retrieval timestamp

### 8.3 Open Architectural Decisions
The following require design decisions during implementation planning:

| Decision | Options | Status |
|----------|---------|--------|
| Source trust scoring algorithm | Rule-based, LLM-assisted, hybrid | Open |
| Duplicate detection across sources | Exact match, fuzzy match, semantic similarity | Open |
| Content validation mechanism | Schema-based, LLM-based, hybrid | Open |
| Source registry format | Static config, dynamic registration, hybrid | Open |

## 9. LLM Boundary

### 9.1 Permitted LLM Uses
- Query understanding and sub-query generation
- Content summarization with source attribution
- Result structuring and normalization
- Language translation if needed

### 9.2 Prohibited LLM Uses
- LLM as standalone source of truth without external retrieval
- Generating business facts not backed by retrieved sources
- Making decisions or recommendations

### 9.3 LLM Transparency Requirement
- Any LLM-processed content must be flagged
- LLM summary must preserve source attribution
- LLM-generated claims without source backing must be clearly marked

## 10. Knowledge Layer Boundary

### 10.1 External Research → Knowledge Layer
External Research produces **Research Results** with evidence and provenance.

Research Results may be:
- Registered as Knowledge Providers for future queries
- Passed to Reasoning layer for analysis
- Stored via Knowledge Ingestion if long-term retention is needed

### 10.2 Knowledge Ingestion Boundary
- Knowledge Ingestion imports/transforms/registers knowledge
- External Research produces research results
- Research Results may be ingested by Knowledge Ingestion if they meet quality criteria
- The two capabilities remain separate; Research does not bypass Ingestion

---

## 11. Reasoning Boundary

### 11.1 External Research Output
Structured research results with:
- Findings organized by topic/question
- Source citations for each finding
- Evidence references
- Retrieval metadata

### 11.2 Reasoning Input
Reasoning consumes research results to:
- Analyze findings
- Draw conclusions
- Make recommendations
- Generate plans

### 11.3 Separation of Concerns
- External Research: "What does the external information say?"
- Reasoning: "What does this mean for our business?"
- Planning: "What should we do about it?"
- Execution: "Do it."
